# Agent Note: 自托管多设备同步

Status: proposed

[English](2026-11-21-self-hosted-sync.md) | 中文

## 问题

备份可以还原用户数据，却无法协调两台运行中的桌面设备各自的修改。复制使用中的 SQLite 文件还会复制设备专属状态，并绕过维护消息树、搜索索引和偏好设置订阅的服务。

## 提案

用户在数据设置中填写服务器 URL 和 bearer 令牌并主动启用同步。独立的 Node 服务器管理自己的 SQLite 修订记录和以 SHA-256 寻址的文件内容，不接触桌面数据库。除回环地址外使用 HTTPS。服务器运营者及所有持有令牌的客户端均能访问所选数据；同步提供商 API 密钥必须单独启用。桌面端优先使用操作系统支持的 Electron safeStorage；没有安全后端时可以为当前进程输入令牌，但绝不以明文持久化。

提供九个独立开关：聊天和消息、提供商和 API 密钥、助手和提示词、MCP 服务器、可移植偏好设置、笔记和知识库、智能体和会话、受管文件和附件，以及其他数据（分组、置顶、标签、小程序、绘画和翻译）。各分类显式列出允许的表和字段。排除外部路径、启动设置、缓存、日志、本地工作区绑定、执行权限和向量索引。区分受管笔记的元数据与 Markdown 内容。导入会话历史不得恢复执行，导入 MCP 定义不得启动服务。

在独立的用户配置数据库中保存同步配置、游标、重试状态及每条记录的规范化哈希。通过扫描发现新增、修改和删除，不改动现有写入路径。服务器先按来源修改时间，再按设备 ID 确定胜出版本，删除标记和恢复也遵循相同规则。经过身份验证的 SSE 事件提示客户端分页拉取；启动、窗口聚焦、手动和定时同步可以补回错过的事件。禁用分类不得删除其数据，也不得自动启用依赖分类。

在同步的桌面写事务中保留记录身份。仅当公开方法无法保留身份、时间戳或通知语义时，在所属服务末尾追加范围受限的同步方法。延后处理缺少依赖或正在生成回复的记录，先写父记录再写子记录，删除时反过来。由本地触发器维护全文索引。仅在提交后刷新所属服务的缓存并通知已打开的视图。不改动桌面数据库结构、迁移、生成的数据或路由文件、旧存储或备份实现。

## 考虑过的替代方案

- 文件或数据库复制无法区分用户数据、物理标识、外部路径和活动连接。
- 使用集中的原始 SQL 写入器会重复实现各领域的不变量，并使缓存与数据库不一致。
- 跟踪每次本地写入可以改善扫描性能，但会在上游的多个服务中引入钩子。

## 验收标准

- AC1 — Ubuntu 运营者可以使用 Docker Compose 或原生 Node/systemd 运行独立服务器并连接两台桌面设备。仅健康检查公开；验证令牌、事件投递、分页以及限大小且校验哈希的文件传输。 (verification: server tests and deployment guide)
- AC2 — 两个已迁移的桌面数据库在离线新增、编辑、删除和恢复后收敛。时间戳相同也有确定结果；重放不产生新修改；切换分类不丢失其历史。 (verification: main integration tests)
- AC3 — 拉取的数据保留消息根节点、外键和本地全文索引。不覆盖正在生成的回复，不遍历受保护的路径，导入记录不能授予本地执行权限。 (verification: main integration tests)
- AC4 — 设置提供九个分类开关、令牌输入、连接测试、同步间隔、手动同步、需确认的本地重置以及实时状态。远端修改提交后无须重启即可更新已打开的视图；回滚不发送通知。 (verification: renderer, IPC and Electron)
- AC5 — 独立同步引擎、独立服务器和仅追加的所属服务方法可分别审查，不改动桌面数据库结构、迁移、生成文件或备份。PR 列出所有已存在文件的变更及实际测试、类型检查和静态检查结果。 (verification: changed-file inspection and project checks)

## 风险

时钟偏差影响最后写入者获胜的结果；这不是文本合并。独立选择分类可能使部分引用暂时无法应用。无法使用操作系统密钥存储时，重启后需重新输入令牌。必须保护服务器目录和令牌：传输加密不是端到端加密。
